# Kaurivo until the first sale: cloud-first demo production

**Owner's present laptop is not powerful enough for Ollama inference.**
Do not install Ollama or insist that a Windows/Codex worker is running.
Kaurivo currently sends authenticated admin `Rakenna demo` requests to
Supabase, dispatches exact UUIDs to GitHub Actions and uses OpenRouter
**only** with explicit `:free` model names. A submitted request is not
a running build; claim status in the job table confirms real start.

## What works now

- Cloud claim of a previously local/Codex rate-limited Koxmatic job was
  verified on 2026-11-12 after the recovery migration and the lifetime
  `attempt <= 3` constraint fix. This proves **started**, not finished.
- No credentials/CRM payloads in static HTML or Realtime wakeups.
- The canonical Master Prompt, source evidence, three creative concepts,
  independent QA and public browser smoke gate remain mandatory.
- The `Rakenna demo` button can create/dispatch a job and show old/new
  URLs **only** after a legitimate finished, verified internal preview.
- When a rate limit appears, preserve the same job and checkpoint, bound
  retries by UTC day and do not switch to paid AI without explicit consent.

## Operator instructions

1. Stop old local Kaurivo PowerShell daemon with Ctrl+C; no Ollama setup.
2. Open https://k4k33.github.io/website-builder-agent/kaurivo/admin/.
3. Use `Rakenna demo` for a prospect. For old local-quota jobs,
   `Jatka pilvessä` allows the one-time cloud recovery. Do not create
   duplicate jobs.
4. Watch the exact job status: `queued` is not running;
   `researching`/`building`/`qa` are real claimed phases;
   `hold` is a blocker; `internal_preview` is verified INTERNAL
   preview, **not** a sold customer-owned editable site.
5. Check the actual GitHub Actions run if research stops, and diagnose
   the specific redacted error. No infinite retry loops.

GitHub's free standard runners in a public repository are currently free,
but third-party free-model access has provider rate limits. Automation
cannot guarantee a 9.5/10 site on zero-cost models or unlimited jobs.
For the first client prospects, keep a separate manual ChatGPT Work
production path if the free cloud model fails visual quality review.

After the first actual sales, compare a GPU-capable new computer with
metered cloud AI by total cost, reliability and validated quality. Never
buy a specific GPU before checking memory requirements and full-site
browser workloads. CMS ownership, customer editing, legitimate photo
rights and consent remain separate customer handover obligations.
