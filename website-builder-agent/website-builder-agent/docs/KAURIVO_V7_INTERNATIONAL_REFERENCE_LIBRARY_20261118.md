## How the V7 Builder must use this library

1. Reference selection is CANDIDATE -> LIVE_CAPTURED -> MULTI-ROUTE_REVIEWED -> BENCHMARK_APPROVED. For candidates, never show `world-class verified` or a 10/10 label.
2. A reviewer scores each candidate with real 390/768/1440 screenshots and at least one service/product and one conversion page; record `design`, `brand_fidelity`, `content_fidelity`, `imagery`, `typography`, `motion`, `conversion`, `performance`, `accessibility`, `AI_looking_risk` and verified awards, date, region.
3. For each new client, prioritize ORIGINAL COMPANY source evidence and images before any reference. Select 2–3 complementary examples from the same sector or adjacent service model. Extract specific design *principles* with screenshot evidence (e.g. service grid, appointment flow, real-work photo), not exact fonts, source images, animations or code.
4. Evaluate new site against its OWN verified identity/needs AND the principles observed in candidate references. Different design languages are allowed; pixel or screenshot similarity to competitor must NEVER be target metric. Spot expert judgment needs independent reviewers and visible citations.
5. Run objective browser QA (all routes, font load, text column widths, click targets, links, media rights, title, favicon, no overflow, real booking/quote path) separately. All hard functional/factual defects must fail regardless of aesthetic score.
6. Blind-test at least 5 newly researched enterprises from unrelated sectors, with a baseline and V7 same-source comparison. Refine process based on root causes. Do not store reference assets as customer-owned assets or scrape/copy third-party protected media.
